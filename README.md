# Setlog 動画アーカイブ

グループ単位で「その日の動画1本」と「0時〜23時それぞれの写真」を残していく、記録アプリ。1日を24コマの写真と1本の動画で振り返れる。

**Supabase (Postgres / Storage) / Vanilla JavaScript (ES Modules) / ビルド不要の単一 HTML**

---

## 作ったもの

身内のグループで日々の記録を溜めるために作った。画面は4つで、ネイティブアプリに近い操作感（sticky ヘッダー、ボトムナビ、セーフエリア対応）にしている。

| 画面 | 内容 |
| --- | --- |
| グループ一覧 | グループの作成と選択 |
| 日別アルバム | そのグループの日付一覧。写真の有無がひと目で分かる |
| 1時間ごとの写真 | **24コマのグリッド**。各コマに写真を1枚ずつ入れ、動画も1本紐づけられる |
| カレンダー | 月表示。投稿がある日に印が付き、タップでその日へ飛ぶ |

## 技術的な判断

### ビルド工程を持たない

全体を **1ファイル（`index.html`、735行）** で完結させ、ビルドツールもパッケージマネージャも使っていない。Supabase のクライアントは `esm.sh` から直接 import している。

```js
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2';
```

身内数人が使うものなので、`npm install` やビルドの手間を挟まずに「ファイルを置けば動く」状態を優先した。HTML / CSS / JS の分割よりも、変更から反映までが短いことを取った判断。

### ハッシュベースの自作ルーティング

フレームワークを使わないため、`location.hash` をパースして画面を切り替える仕組みを自分で書いた。

```
#/                                → グループ一覧
#/group/:groupId                  → 日別アルバム
#/group/:groupId/day/:date        → 1時間ごとの写真
#/calendar                        → カレンダー
```

`hashchange` で `render()` を呼び、ルートに応じたレンダラへ振り分ける。URL がそのまま状態になるので、ブラウザの戻るボタンが期待どおりに動く。

### ハマった点: 非 ASCII 文字を含むオブジェクトキー

日本語のファイル名のまま Supabase Storage へアップロードすると、オブジェクトキーが通らずアップロードが失敗した。元のファイル名をキーに使うのをやめ、**非 ASCII 文字を含まないキーを生成する**方式に変更して解決した（コミット `Fix storage upload: avoid non-ASCII characters in object key`）。

併せて、アップロードしたファイルの **SHA-256 ハッシュ**（`crypto.subtle.digest`）を保存している。同じ動画を上げ直したかどうかを判定するため。

### UI 面

- 写真をタップすると拡大表示するライトボックス。そこから直接「差し替え」もできる
- `env(safe-area-inset-bottom)` でボトムナビが iPhone の下端に隠れないようにしている
- 写真削除時は Storage のオブジェクトと DB の行を両方消す。投稿ごと削除する場合は、紐づく写真をまとめて削除してから投稿を消す

## データ構造

```
groups         : id, name, created_at
posts          : id, group_id, post_date, video_url, video_hash
hourly_photos  : id, post_id, hour_label, ...
```

Storage バケットは `setlog-media`。

## 使い方

`index.html` をブラウザで開くか、任意の静的ホスティングに置くだけ。別途セットアップは不要（Supabase プロジェクト側にテーブルとバケットが必要）。

## 制約

- **認証を持たない。** anon キーが HTML に含まれており（Supabase の設計上クライアントに公開してよいキーだが）、アクセス制御は Supabase 側の RLS に委ねる前提。URL を知っている身内だけが使う想定で作っている
- 1日1投稿・1時間1枚の固定構造。それ以上の枚数は入れられない
- 動画の変換・圧縮はしておらず、撮影したファイルをそのまま保存する
